## E1 치수 스타일

- 템플릿(`template.dwg` 사본): DIM330·DIM270 모두 `AcadAnnotative` XDATA 플래그 1(주석). 스타일 DIMSCALE 200, DIMTXT 3.3·2.7. 템플릿 CANNOSCALE `1:100`, INSUNITS 4.
- 주석 DIM330으로 1/100 치수를 넣으면 치수 문자 높이 **330**(DXF 치수 블록의 MTEXT 높이). 표준(A3 1/100에서 165)의 2배다. 지금 스킬 절차(`-DIMSTYLE _R DIM330` → `DIMSCALE 50` → 치수)로 그리면 이 크기가 나온다. 당산동 작업에서 겪은 '주석 축척 치수' 문제와 같다.
- 비주석 전환: COM `SetXData`로 플래그 0을 쓰는 것도 받아들여졌고, LISP `(entmod (append (entget (tblobjname "DIMSTYLE" "DIM330")) '((-3 ("AcadAnnotative")))))`로 XDATA를 지우면 DXF에서 주석 표시가 사라진다(DIMANNO 0).
- 전환 뒤 DIMSCALE 50 → 문자 **165**, DIMSCALE 100 → **330**. 비주석 규칙(DIMSCALE = k/2)과 맞다.
- 관찰: 스타일 전환 뒤 DIMSCALE을 바꾸면 치수마다 덮어쓰기(ACAD XDATA)가 붙는다. T2·T5에서 '축척별 DIMSCALE 덮어쓰기'로 갈지 정한다.
- T2 지침: 템플릿의 두 스타일에서 `AcadAnnotative` XDATA를 `entmod`로 지운다. 표준매뉴얼·스킬의 치수 절도 함께 고친다.

## E2 내보내기, E3 핸들 일치

synthetic 사본에 문자 하나를 더해 '저장 안 함' 상태(라이브 34개)를 만든 뒤 비교했다.

| 후보 | 출력 | 이름·경로·활성 | 미저장 상태 | 데이터(개수·한글·속성) | 핸들 | 시간 |
|---|---|---|---|---|---|---|
| COM `Export(이름, "DXF", 빈 선택 세트)` 확장자 없이 | AC1032 | 유지 | **유지** | 일치(미저장 문자 포함) | **100%** | 0.29초 |
| COM `Export`, 이름에 `.dxf` 포함 | 실패(예외) | 유지 | 유지 | — | — | — |
| `-WBLOCK` 도면 전체 → 열어서 `SaveAs(…, 61)` | AC1027 | 유지 | 유지 | 일치 | 0% | 2.9초 |
| COM `Wblock`(전체 선택) → `SaveAs(…, 61)` | AC1027 | 유지 | 유지 | 일치 | 0% | 3.2초 |

- 실패 때: 없는 드라이브로 `Export` → COM 예외, 원본·활성 문서 그대로. `DXFOUT` → 오류 신호 없이(CMDACTIVE 0) 파일만 안 생김. 그래서 내보낸 뒤 파일 존재를 확인해야 한다.

## E4 삽입·분해

`spikes/gen_dxf.py`가 template.dxf 위에 표준 레이어(ByLayer) 객체 11개(선·경량 폴리선·원·호·한글 MC 문자·MTEXT·축열 버블 속성 X9·섬 해치·SOLID 해치·비주석 치수·LIM PHANTOM 선)를 만들고 모두 `ARCAID` XDATA(`op=`, `oid=`, `path=`, `ver=`)를 달았다. synthetic 사본마다 네 방법으로 넣고, 태그(`oid`)로 짝지어 비교했다.

| 방법 | 11개 | 100개 | 남는 것 | 비고 |
|---|---|---|---|---|
| (가) `-INSERT 파일.dxf` + `EXPLODE` | 모두 보존 | 보존 | 블록 정의 `gen` | 명령행 |
| (나) DWG로 저장 → `InsertBlock` → `Explode` → 참조 삭제·정의 삭제 | 모두 보존 | 보존 | 없음 | 임시 DWG, 절차 김 |
| (다) COM `Document.Import(파일.dxf, 원점, 1)` | 모두 보존 | 보존 | 없음 | 호출 하나 |
| (라) DXF를 문서로 열어 `CopyObjects` | 모두 보존 | 보존 | 없음 | 두 번째 문서 |

- 보존 항목: 개수·종류, 레이어, 색(ByLayer), 선종류(LIM PHANTOM 포함), 한글 문자열, 블록 속성값, XDATA 4개 값. 좌표는 선 끝점이 0.01mm 안에서 일치했다(정렬 문자의 기준점은 COM `InsertionPoint`와 DXF 기준점이 달라 비교에서 뺐다).
- 해치: DXF 경로로 넣은 해치는 화면에 정상 표시된다(COM `AddHatch` 문제 없음). 섬은 안쪽 루프에 `BOUNDARY_PATH_OUTERMOST`(16) 플래그를 주고 방향을 반대로 해야 구멍이 생긴다(면적 3,000,000). 플래그 없이 넣으면 GstarCAD가 구멍을 무시한다(면적 4,000,000).
- 속도: template.dxf 전체를 담은 DXF는 객체 수와 관계없이 Import에 약 6초(정의 읽기 비용). 레이어만 정의한 최소 DXF는 선 1,000개가 **0.06초**. 대상 도면의 같은 이름 정의가 어차피 우선하므로(E5), 생성 DXF에는 대상에 없는 정의(블록 등)만 넣는다.
- 결정안: 삽입은 (다) Import 우선. Import는 단위를 환산하지 않으므로(E8) 적용 전에 단위 일치를 확인한다. 실패한 객체 종류는 없어 COM·LISP 직접 생성 대상은 아직 없다.

## E5 같은 이름 정의

대상 사본에서 DIM330 DIMTXT를 5로, 레이어 CEN 색을 3으로 바꾸고 버블 블록에 원을 하나 넣은 뒤 Import했다.

- 결과: 세 정의 모두 대상 것이 남았다(생성 DXF의 정의는 무시).
- 넣은 치수의 문자는 처음 165였지만, 1mm 옮겼다 되돌려 다시 계산시키자 **250**(대상 DIMTXT 5 × DIMSCALE 50)이 됐다.
- 적용 전 감지: 새 스냅샷(Export)과 template.dxf의 DIMSTYLE·LAYER·BLOCK 정의를 ezdxf로 비교해 세 차이를 모두 잡았다. LISP `(tblsearch "DIMSTYLE" "DIM330")`로도 값을 읽을 수 있다.
- D3의 '같은 이름, 다른 정의면 덮어쓰지 않고 멈춤' 규칙이 필요함을 확인했다.

## E6 Undo 복구

시나리오마다 새 사본에서 표시 선(그 전 작업)을 그은 뒤, 묶음 안에서 Import하고 `UNDO 1`을 보냈다.

| 시나리오 | 복귀 | 표시 선 |
|---|---|---|
| A: COM `StartUndoMark` → Import → `EndUndoMark` | 됨 | 남음 |
| B: 명령행 `UNDO _BE` → COM Import → `UNDO _E` | 됨 | 남음 |
| B2: `UNDO _BE` + `-INSERT` + `EXPLODE` + `UNDO _E`를 한 문자열로 | 됨 | 남음 |
| C: 묶음 안에서 Import 뒤 `draw_line`(자체 Undo 묶음) → 예외 | **안 됨**(11개 남음) | 남음 |
| C2: 묶음 안에서 Import 뒤 바로 예외(겹친 묶음 없음) | 됨 | 남음 |
| D: 묶음 안에서 Import 뒤 명령 입력 대기 → `cancel_command` | **안 됨**(11개 남음) | 남음 |
| 대안: `op` 태그로 찾아 지우기(LISP `ssget` + `entdel`) | 됨(11개 삭제, 2.3초) | 남음 |

- GstarCAD에서는 묶음 안의 다른 Undo 묶음이나 명령이 `UNDO 1`의 범위를 바꾼다. 실제 Undo는 '되돌렸다고 가정'하면 안 되고, 핸들 집합으로 복귀를 확인해야 한다.
- 결정안: 보호된 경로는 묶음 안에서 겹친 묶음(기존 `draw_*`의 `_undo_group`)과 명령을 쓰지 않고 COM만 쓴다. 복귀 확인에 실패하면 0-A는 추가만 하므로 `op` 태그로 지우고 남은 것이 없는지 확인한다. 그래도 확인하지 못하면 '확인 불가'로 보고한다.

## E7 XDATA 조회

`op` 두 개(e7a·e7b, 각 500)와 최소 DXF 1,000개를 넣어 태그 객체 2,000개를 만들었다.

- LISP `(ssget "_X" '((-3 ("ARCAID"))))`: 2,000개, 0.8초. `op=e7a`로 거르는 반복: 500개 정확, 0.84초.
- 스냅샷: Export 0.26초 + ezdxf 읽기 0.25초 + 거르기 0.005초, 500개 정확. 핸들도 함께 얻는다.

## E8 단위·경로

| 대상 $INSUNITS | Import 뒤 6000mm 선 | -INSERT(DWG) 뒤 |
|---|---|---|
| 4 (mm) | 6000 | 6000 |
| 6 (m) | **6000** (환산 안 함) | **6.0** (환산함) |
| 0 (미정) | 6000 | 6000 |

- 배율 1000인 블록 참조는 스냅샷에서 `xscale 1000`으로 보인다. 단위 섞임 경고에 쓸 수 있다.
- 한글·공백 경로(`한글 경로\`): COM Open·SaveAs, `-INSERT "경로"`, `InsertBlock`, `Import`, `Export`, LISP `open` 모두 동작. LISP가 쓴 한글 내용은 CP949(`run_lisp`는 mbcs로 읽어 문제없음). SaveAs 직후 LISP 호출 한 번이 결과 파일을 못 만들었으나 따로 다시 시험하면 모든 조합이 됐다(일시적 실패로 본다).
- 결정안: D5의 '단위가 다르거나 미정이면 적용하지 않음'을 유지한다(Import는 조용히 그대로, -INSERT는 조용히 환산). 작업 폴더 ASCII 규칙은 기본값으로 두되 막는 조건으로 쓰지 않는다.

## E9 출력

- COM으로 `ConfigName = "DWG To PDF.pc3"`, `StyleSheet = "HEO(2020)_A3.ctb"`(설치 확인), 용지 `A3`, 사용자 축척 1:100, `BACKGROUNDPLOT 0`(끝나고 복원)으로 `Plot.PlotToFile` 출력 성공.
- 출력 범위: '범위 전체'·'화면'은 정상, **'창'(PlotType 4 + `SetWindowToPlot`)은 순서를 바꿔도 빈 PDF**. 출력 범위로 줌한 뒤 '화면'으로 출력하면 된다.
- 확인: A3(420×297) 위 X1–X3(12,000mm)이 120mm로 1/100 축척이 맞고, CEN(출력 안 함 레이어)은 나오지 않으며 CON이 굵게 나온다(`e9_auto.pdf`).
- 손 출력본 비교(2026-10-14, `spikes/e9_compare.py`): 사용자가 같은 도면을 평소 방법으로 출력한 `manual.pdf`의 출력기는 **Microsoft: Print To PDF**(Windows 기본 PDF 프린터)였다. 자동 출력은 `DWG To PDF.pc3`.
  - 같은 것: 용지 A3(420×297), 축척 1/100(X1–X3 12,000mm = 120mm), 객체 구성, 선굵기 등급 2개의 비율(약 2:1).
  - 다른 것: 선굵기 절대값이 출력 장치 해상도로 반올림돼 다르다(손 0.254·0.127·0.085mm, 자동 0.339·0.169·0.042mm). 손 출력은 문자를 글꼴 문자(검색 가능)로, 자동 출력은 선으로 담았다. 그림 위치가 조금 다르다(출력 범위 중심 차이). 래스터 비교 시 다른 픽셀 1.1%.
  - 결론: 계획대로 `plot` 결과는 '시험 출력'으로 표시한다. 정식 출력기는 `DWG To PDF.pc3`로 정했다(2026-10-14 사용자 결정, 저장 창 없이 파일로 출력됨을 E9에서 확인). 손 출력도 같은 출력기로 하면 결과가 같아진다.
