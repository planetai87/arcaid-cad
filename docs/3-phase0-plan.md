# arcaid-cad 0단계 실행 계획

Oct 14, 2026 · @Jeonglo Choi

0-A를 작업 11개(T0\~T10)로 나눠 진행한다. 사전 검증(T0)으로 CAD 동작을 먼저 확인하고, 당산동 기준층 평면 재현(T10)으로 0-A 통과를 판정한다. 이동·삭제를 다루는 0-B는 0-A를 통과한 뒤 별도 계획으로 쓴다.

## 전제와 범위

**전제가 되는 결정** ([구조 결정](https://claude.ai/code/artifact/48c5835e-76eb-455b-9841-e7da7bd24409) 기준)

- 확정: D1 역할 경계, D2 툴과 결과 형식, D3 표준 파일(주석 축척 미사용), D4 도면 읽기, D5 변경 적용, D7 대상 CAD, D8 외부 전송(허용 목록 방식), D9 DWG 기준 원칙
- D6 변환 방법은 T0 결과로 확정했다(2026-10-14): 스냅샷은 COM Export, 생성 DXF는 R2013.
- D8은 권장안인 B안(허용 목록)으로 확정된 것으로 보고 계획을 짰다.

**0-A 범위**

- 새 객체 추가(`draw_batch`)와 표준 위반의 레이어·색 수정(`check_standard`)을 보호된 경로로 지원한다.
- 읽기(`export_snapshot`, `read_drawing`), 표준 검사, 표준 프로파일, CLI, 스킬 개정을 함께 끝낸다.
- 대상 CAD는 GstarCAD 2021이다. BricsCAD는 T10을 통과한 뒤 같은 시험을 한 번 더 돌린다.

**이 문서에서 다루지 않는 것**: 0-B(이동·삭제·일반 속성 변경)와 1단계 이후 기능(`project.yaml`, 법규 분석, 생성기). 기간은 로드맵대로 진행 속도를 보고 정하고, 작업마다 끝난 날짜를 기록해 둔다.

## 작업 순서

&#91;embedded content: 작업 의존 관계 · T0\~T10\]

T0과 T1은 동시에 시작할 수 있고, T2 뒤로는 T3·T5·T7이 나란히 진행된다. T6과 T8은 T4와 T5가 모두 끝나야 시작하고, T10은 T8과 T9가 끝난 뒤에 한다.

## T0 · 사전 검증

**목적**: 구조 결정이 기대는 CAD 동작을 GstarCAD 2021에서 직접 확인하고, D6(변환 방법)을 확정한다. 다른 작업보다 먼저 하고, 결과에 따라 이 계획을 고친다.

**방법**: 저장소 `spikes/` 폴더에 실험 스크립트를 두고, 회사 템플릿으로 만든 합성 시험 도면(그리드, 실 몇 개, 여러 객체 종류)으로 돌린다. 실무 도면은 쓰지 않는다. 결과는 `docs/spike-report.md`에 항목별 통과·실패·관찰로 남기고, 실험 코드는 제품 코드로 옮기지 않는다.

| 실험 | 확인할 것 | 실패하면 |
| --- | --- | --- |
| E1 치수 스타일 | 템플릿 DIM330·DIM270의 주석 여부. 비주석으로 바꾼 뒤 1/100·1/200 표시와 출력 비교 | 판별이 어려우면 두 스타일을 비주석으로 새로 정의해 템플릿에 넣는다 |
| E2 내보내기 | Export·WBLOCK·DXFOUT 세 후보를 D6의 비교 기준(문서 이름·경로·미저장 상태 유지, R2013 출력, 데이터 보존, 소요 시간)으로 시험 | 세 후보가 모두 실패하면 저장된 DWG만 읽고, 읽기 전에 사용자에게 저장을 요청한다 |
| E3 핸들 일치 | DXF 사본의 핸들이 열린 DWG의 핸들과 같은지 | 다르면 레이어·색 수정 대상은 COM 조회로 다시 찾는다 |
| E4 삽입·분해 | 생성 DXF(R2013)를 열린 도면에 넣은 뒤 레이어·색·선종류·한글 문자·블록 속성·해치·좌표(0.01mm)·XDATA가 유지되는지. DXF를 바로 넣지 못하면 DWG로 바꿔 넣어 본다 | 유지되지 않는 객체 종류는 COM·LISP로 직접 만든다(D5 추가 경로) |
| E5 같은 이름 정의 | 대상 도면에 다른 정의의 DIM330이 있을 때 삽입 결과와, 적용 전에 그 차이를 잡을 수 있는지 | 스냅샷으로 못 잡으면 적용 전에 COM으로 스타일 속성을 비교한다 |
| E6 Undo 복구 | 묶음 뒤 Undo 한 번으로 삽입 전체가 사라지는지, 중간에 일부러 실패시켰을 때 복귀를 확인할 수 있는지 | 0-A는 추가만 하므로, 되돌리기를 '태그(`op`)로 찾아 지우고 남은 것이 없는지 확인'으로 바꾼다 |
| E7 XDATA 조회 | 앱 이름과 `op` 값으로 객체 찾기(LISP `ssget` 필터)의 정확도와 속도 | 느리면 스냅샷 DXF에서 찾고 핸들로 접근한다 |
| E8 단위·경로 | mm·m·단위 미정 도면과 블록 배율, 한글·공백 경로에서 COM·LISP·삽입 동작 | 작업 폴더는 영문 경로로 고정하고, 단위 미정 도면은 읽기만 한다 |
| E9 출력 | 회사 CTB를 지정한 PDF 출력이 손으로 출력한 결과와 같은지 | 다르면 `plot` 결과를 시험 출력으로만 표시한다 |

**완료 기준**: E1\~E9 결과가 보고서에 있고, D6을 확정해 구조 결정 문서에 반영했으며, 실패한 항목마다 고른 대안이 해당 작업 명세에 들어갔다.

**결과** (2026-10-14, 자세한 내용은 저장소 `docs/spike-report.md`): E1~E8 통과 또는 대안 확정, E9는 출력은 되지만 사무소 손 출력과 출력기가 달라 정식 출력기를 정할 때까지 '시험 출력'(T7 참고). T0 완료 2026-10-14.

| 실험 | 결과 | 고른 방법·대안 |
| --- | --- | --- |
| E1 | 템플릿 DIM330·DIM270은 주석. 1/100에서 치수 문자 330(표준 165의 2배) | LISP `entmod`로 `AcadAnnotative` XDATA를 지워 비주석 전환(DIMSCALE 50·100에서 165·330 확인) |

| E5 | 대상 정의가 남고, 넣은 치수는 다시 계산되면 대상 스타일을 따름 | 스냅샷과 template.dxf 정의를 비교해 멈춤 |
| E6 | 깨끗한 묶음은 `UNDO 1`로 복귀, 겹친 묶음·명령이 끼면 실패 | 묶음 안에서 COM만, 실패 시 `op` 태그로 지우기 |
| E7 | `op`로 정확히 찾음: LISP 0.8초, 스냅샷 0.5초 | 둘 다 가능, 스냅샷 우선 |

| E9 | 회사 CTB·A3·1/100 PDF 출력 성공. 창 방식은 빈 PDF | 출력 범위로 줌한 뒤 화면 방식. 손 출력본(Microsoft Print to PDF)과 축척·배치·선굵기 등급 비율은 같고 선굵기 절대값·문자 처리가 다름 → 정식 출력기를 정할 때까지 '시험 출력' |

## 작업 명세

작업마다 목적, 바뀌는 파일, 완료 기준, 테스트를 적는다. 작업 하나가 Claude Code의 작업 단위(브랜치 하나, PR 하나)다.

### T1 · 저장소 정리와 엔진 골격

- **목적**: 엔진을 CAD에서 떼어낼 자리를 만들고, 원본 저장소에서 남은 코드를 걷어낸다.
- **바뀌는 파일**
  - 삭제: `src/nlp_processor.py`, `server.py`의 `process_command`와 관련 코드
  - 신규: `src/engine/`(패키지), `src/engine/results.py`(D2 결과 형식의 pydantic 모델), `tests/engine/`, `tests/cad/`(Windows·CAD 전용 표시), `.github/workflows/engine-tests.yml`
  - 신규: `CLAUDE.md`(문서 위치와 작업 규칙), `docs/`(이 계획과 구조 결정의 Markdown 사본)
  - 수정: `pyproject.toml`, `requirements.txt`(ezdxf, PyYAML, pytest 추가)
- **완료 기준**: 엔진 패키지가 `win32com` 없이 불러와진다. 결과 모델로 만든 JSON이 스키마 검증을 통과한다. 남은 MCP 툴 38개가 그대로 동작한다. 등록된 MCP 설정이 깨지지 않도록 실행 경로(`src/server.py`)는 바꾸지 않는다.
- **테스트**: `win32com` 불러오기 금지 테스트, 결과 모델 직렬화 테스트, GitHub Actions에서 Linux로 엔진 테스트 실행.

완료: 2026-10-14(PR #1). 보완한 것: `nlp_processor`의 색 이름 표는 그리기 도구가 쓰므로 `src/colors.py`로 옮김, MCP 툴 목록 고정 테스트(`tests/mcp`, Windows), pywin32는 Windows에서만 설치.

### T2 · 표준 프로파일과 템플릿 정비

- **목적**: 회사 표준을 코드가 읽는 단일 원본으로 만든다(D3).
- **바뀌는 파일**
  - 신규: `standards/heo-2026/`의 `profile.yaml`, `layers.yaml`, `text.yaml`, `dimensions.yaml`, `blocks.yaml`
  - 신규: `src/engine/standards.py`(pydantic 모델, 로더, 표준·스키마 버전)
  - 신규: `tools/template/export_template_dxf.py`(템플릿 → `template.dxf`), `tools/standards/gen_references.py`(스킬 references 표 생성)
  - 수정: `skills/cad-drawing-standard/assets/회사표준_템플릿.dwg`(E1 결과에 따라 DIM330·DIM270 비주석 전환)
  - MCP 등록: `get_standard`
- **완료 기준**: 템플릿과 YAML이 레이어·문자 스타일·치수 스타일·블록 정의에서 일치한다. 템플릿 해시가 `profile.yaml`에 있다. `get_standard`가 레이어 용도와 문자 높이를 돌려준다. 템플릿 변경은 표준매뉴얼 개정과 함께 반영했다.
- **테스트**: YAML 스키마 검증, `template.dxf`와 YAML 일치 테스트, 일부러 다르게 만든 템플릿에서 '불일치'를 보고하는지.

T0 반영: 템플릿의 DIM330·DIM270 비주석 전환은 LISP `entmod`로 치수 스타일의 `AcadAnnotative` XDATA를 지운다(E1, 2026-10-14 전환 결정). `layers.yaml`에 레이어별 허용 선종류를 두어 LIM의 PHANTOM·CENTER를 표준으로 다룬다. 치수를 '축척별 DIMSCALE 덮어쓰기'로 넣을지 정한다(스타일 전환 뒤 DIMSCALE을 바꾸면 치수마다 덮어쓰기가 붙는다).

완료: 2026-10-14(PR #3). 템플릿 DIM330·DIM270 비주석·스타일 DIMSCALE 50, `standards/heo-2026`(YAML 5개 + `template.dxf`, 해시), `get_standard`(툴 39개), 스킬 references 표 생성. 표준매뉴얼 DWG 반영은 사무소 확인 사항(개정 문구: 저장소 `docs/manual-revision-2026-10.md`).

### T3 · 스냅샷과 도면 읽기

- **목적**: 열린 도면을 문서 이름을 바꾸지 않고 DXF 사본으로 만들고, 엔진이 구조화해 읽는다(D4, D6).
- **바뀌는 파일**
  - MCP: `export_snapshot`(E2에서 고른 방법), 작업 폴더 경로 검사, `save_drawing`에 DXF 확장자 거부 가드
  - 엔진: `src/engine/snapshot.py`(스냅샷 ID, 메타, 닫힌 파일 캐시), `src/engine/read.py`(`read_drawing`: 추출, 판독, `out_of_scope`)
  - 수정: `src/cad_controller.py`(내보내기, 닫힌 파일 열기·내보내기·닫기)
- **완료 기준**: 내보낸 뒤에도 열린 문서의 이름·경로·미저장 상태가 그대로다. 합성 시험 도면의 그리드 축과 실명이 빠짐없이 읽힌다. 단위가 mm가 아니면 경고하고, 레이아웃·Xref 내부는 `out_of_scope`로 나온다.
- **테스트**: 엔진은 ezdxf로 만든 시험 DXF(mm·m·단위 미정, 비표준 레이어 포함)로 한다. CAD 연동은 합성 시험 도면을 내보낸 뒤 문서 상태를 비교한다.

T0 반영: `export_snapshot`은 COM `Export(확장자 없는 이름, "DXF", 빈 선택 세트)`로 하고, 내보낸 뒤 파일이 있는지 확인한다. 스냅샷은 AC1027·AC1032를 받는다. DXFOUT(미저장 표시를 지움)과 SaveAs DXF(문서가 DXF로 바뀜)는 쓰지 않는다. 닫힌 파일 일괄 변환 속도는 여기서 잰다.

### T4 · 표준 검사

- **목적**: 표준 검사를 AI가 아닌 코드로 처리한다(D2, D3).
- **바뀌는 파일**: `src/engine/check.py`(`check_standard`), MCP 등록. 자동 수정(`fix`)은 T6의 보호된 경로에 연결한다.
- **검사 항목**: 비표준 레이어, 레이어 `0` 사용, ByLayer가 아닌 색·선종류, 문자 스타일·높이, 치수 스타일과 DIMSCALE, 주석 축척 객체, 표준 블록의 삽입 레이어, 대상 도면의 같은 이름 정의 불일치. 축척 k는 요청에서 받고, 없으면 1/100으로 보고 `assumptions`에 적는다.
- **완료 기준**: 위반마다 위치·핸들·고칠 값이 나온다. 레이어·색처럼 정답이 정해진 위반에는 고칠 목록이 붙는다. 검사하지 못한 항목은 `unchecked`, 범위 밖은 `out_of_scope`로 나뉜다. 당산동 작업 때 AI가 하던 마무리 검사를 대신할 수 있다.
- **테스트**: 위반을 일부러 심은 시험 DXF마다, 기대한 위반 목록과 정확히 일치하는지 비교한다(골든 파일).

T0 반영: 'ByLayer가 아닌 선종류' 검사는 `layers.yaml`의 허용 선종류(LIM의 PHANTOM·CENTER)를 예외로 둔다. 같은 이름 정의 불일치는 스냅샷과 template.dxf의 DIMSTYLE·LAYER·BLOCK 정의를 비교해 잡는다(E5에서 세 종류 모두 잡힘).

### T5 · 객체 명세와 DXF 작성

- **목적**: AI가 좌표 대신 배치 규칙을 넘기면, 엔진이 표준에 맞는 DXF를 쓴다(D1, D5).
- **바뀌는 파일**
  - `src/engine/spec.py`: 객체 명세 스키마(단위 mm, WCS, 지원 객체, 배치 규칙, 프로파일·스냅샷 ID)
  - `src/engine/layout.py`: 반복·대칭·그리드 기준 배치 전개
  - `src/engine/write.py`: `template.dxf` 위에 작성, 레이어·스타일 강제, XDATA `ARCAID` 태그(`op`, `oid`, `path`, `ver`)
- **지원 객체(0-A)**: 선, 폴리라인, 원·호, 문자(정렬 포함), 블록 참조(속성 포함), 해치(섬 포함), 선형 치수. 치수는 E4 결과에 따라 COM 직접 생성으로 돌릴 수 있다.
- **완료 기준**: 같은 명세면 같은 DXF(객체·좌표·태그)가 나온다. 표준에 없는 레이어·스타일은 쓰지 않는다. 지원하지 않는 객체가 명세에 있으면 작성 전에 거부한다.
- **테스트**: 명세 → DXF → 다시 읽기 왕복 테스트, 배치 규칙 전개 단위 테스트, 당산동형 객실 배치(반복·대칭) 명세의 골든 비교.

T0 반영: 생성 DXF에는 대상 도면에 없는 정의(블록 등)만 담는다. `template.dxf` 전체를 담으면 넣는 데 6초, 레이어만 담으면 객체 1,000개에 0.06초였다. 섬이 있는 해치는 안쪽 루프에 `BOUNDARY_PATH_OUTERMOST`(16) 플래그를 주고 방향을 반대로 해야 GstarCAD가 구멍을 만든다. 치수는 DXF 경로로 보존돼 COM 직접 생성으로 돌리지 않는다.

### T6 · 보호된 적용 경로

- **목적**: D5 규칙대로, 확인을 통과하지 못하면 아무것도 바꾸지 않는 적용 경로를 만든다.
- **바뀌는 파일**
  - MCP `draw_batch`: 명세 검증 → 스냅샷 → DXF 작성 → 적용 직전 확인 → Undo 그룹 안에서 삽입·분해 → 결과 확인 → 기준 상태(`state`) 저장 → 검사 → 보고
  - `src/engine/apply.py`: 재실행 판정(`op`와 입력 해시, 예상 `oid` 목록), 객체 종류별 기준 상태 해시, 충돌 판정
  - `src/cad_controller.py`: Undo 그룹 닫힘 확인, 실제 Undo 실행과 복귀 확인(E6이 실패하면 태그로 찾아 지우기), XDATA 읽기·쓰기, 타임아웃·연결 끊김 뒤 후속 변경 차단
  - `check_standard`의 `fix`: 레이어·색 수정을 같은 경로로 적용한다. 대상의 읽을 때 레이어·색을 담아 적용 직전에 비교한다.
- **완료 기준**
  - 같은 요청을 다시 보내면 건너뛰고 '이미 완료'로 보고한다. 같은 `op`에 다른 입력이면 충돌로 멈춘다. 일부 객체를 지운 뒤 다시 보내면 완료로 보지 않고 멈춘다.
  - 적용 중 일부러 실패를 일으키면 원래 상태로 돌아오고, 그 사실을 확인해 보고한다. 확인하지 못하면 '확인 불가'로 보고한다.
  - 엔진 객체의 문자·블록 속성·레이어를 손으로 바꾸면 다음 작업에서 충돌로 잡힌다. 보호된 경로로 바꾼 것은 잡히지 않는다.
  - 결과가 D2 형식을 따르고 `status`가 실제 상황과 맞다.
- **테스트**: 위 시나리오를 `tests/cad/` 연동 테스트로 자동화하고(Windows), 판정 로직은 엔진 단위 테스트로 확인한다.

T0 반영: 삽입은 COM `Document.Import`로 하고, 대상 단위가 mm가 아니면 적용하지 않는다(Import는 단위를 환산하지 않음). Undo 묶음 안에서는 COM 호출만 쓴다 — 기존 `draw_*`처럼 자체 묶음을 여는 함수나 명령이 끼면 `UNDO 1`이 복귀하지 못했다(E6). 복귀는 핸들 집합으로 확인하고, 실패하면 `op` 태그로 찾아 지운 뒤 남은 것이 없는지 확인한다. 태그 조회는 스냅샷(0.5초)을 우선한다.

추가(T2에서 발견): CAD에 명령·LISP를 보내기 전에 대상 문서가 활성인지 확인한다. GstarCAD는 명령을 활성 문서로만 보내, 문서를 닫거나 연 직후에 보낸 LISP가 어느 도면에서도 실행되지 않은 적이 있다. `cad_controller`의 `send_command`·`run_lisp`에 넣는다(T7과 공통).

### T7 · MCP 툴 정리와 외부 반환 필터

- **목적**: D2의 툴 목록을 맞추고, D8의 허용 목록을 실제로 적용한다.
- **바뀌는 파일**: `src/server.py`, `src/cad_controller.py`, `config/egress.yaml`(신규)
  - 신규 툴: `new_from_template`, `ensure_standard_layers`, `get_selection`, `plot`(회사 CTB 지정 PDF)
  - 제거: `create_layer`, `new_drawing`
  - 툴 설명문에 보호 여부 표시(저수준 툴은 '보호되지 않음')
  - 외부 반환 필터: 모든 MCP 결과를 `config/egress.yaml`의 허용 목록으로 걸러 AI에 돌려주고, 전체 결과는 PC의 작업 폴더에 남긴다. 목록에 없는 필드는 보내지 않는다. `screenshot`은 설정에서 켜 둔 경우에만 동작한다.
- **완료 기준**: 툴 목록이 D2 표와 같다. 새 툴은 D2 결과 형식으로 답한다. 허용 목록에 없는 필드가 AI 반환 결과에 나오지 않는다. `plot` 결과는 E9 기준을 통과하거나 '시험 출력'으로 표시된다.
- **테스트**: 툴별 연동 테스트, 툴 목록 고정 테스트(의도하지 않은 추가·삭제 방지), 경로·파일명·문자 내용을 넣은 결과로 필터 테스트.

T0 반영: `plot`은 출력 범위로 줌한 뒤 '화면' 방식으로 출력한다. GstarCAD 2021 COM의 '창' 방식(`SetWindowToPlot`)은 빈 PDF를 낸다. `HEO(2020)_A3.ctb` + `DWG To PDF.pc3` + A3 + 1/100 출력은 축척까지 맞았고, 손 출력본과의 비교(E9)로 '시험 출력' 표시 여부를 정한다.

E9 결과(2026-10-14): 사무소 손 출력은 Windows 기본 PDF 프린터(Microsoft Print to PDF)로 했다. 자동 출력(`DWG To PDF.pc3`)과 축척·배치·선굵기 등급의 비율은 같지만, 선굵기 절대값(장치 해상도 반올림, 예 0.254mm와 0.339mm)과 문자 처리(글꼴 문자와 선)가 다르다. T7 착수 전에 정식 출력기를 정한다(Microsoft Print to PDF로 맞추거나 DWG To PDF를 정식으로 채택). 정하기 전 `plot` 결과는 '시험 출력'으로 표시한다.

### T8 · CLI

- **목적**: 엔진 툴을 CAD 없이 파일 단위로 실행한다(D1).
- **바뀌는 파일**: `src/cli.py`, `pyproject.toml`(명령 `arcaid`). 명령은 `arcaid read <파일.dxf>`, `arcaid check <파일.dxf> --scale 100`, `arcaid build <명세.json> -o <출력.dxf>`.

- **테스트**: CLI·MCP 결과 동일성 테스트, GitHub Actions 실행.

### T9 · 스킬 개정

- **목적**: 스킬이 새 툴과 표준 파일을 기준으로 일하게 한다.
- **바뀌는 파일**: `skills/cad-drawing-standard/SKILL.md`, `references/`(표는 T2 스크립트로 생성)
  - 작업 흐름: `new_from_template` → `export_snapshot`·`read_drawing` → 명세 작성 → `draw_batch` → `check_standard` → 보고

  - 태그가 붙은 엔진 객체를 저수준 툴·`send_command`·`run_lisp`로 고치지 않는다는 규칙
  - 치수 규칙을 비주석 기준(DIMSCALE = k/2) 하나로 정리
  - '도구의 한계' 절에서 새 툴로 해결된 항목 삭제
- **완료 기준**: 스킬에 표준 숫자가 직접 적혀 있지 않다(생성된 표 제외). 새 툴만으로 T10 절차를 따라갈 수 있다.
- **테스트**: claude.ai 업로드용 zip 생성 확인, T10 리허설.

## T10 · 0-A 통과 시험

**목적**: 로드맵의 0단계 확인 사례인 당산동 기준층 평면을 즉석 LISP 없이 새 툴 호출만으로 재현하고, 0-A 통과를 판정한다.

**절차**

1. 당산동 원본 도면(코어·그리드만 있는 상태)의 사본을 준비한다. 원본은 단위 헤더가 m($INSUNITS 6)인데 좌표는 mm이고 그리드·실명이 비표준 레이어(A-CEN, A-ROOM)에 있으므로, 사본의 단위를 mm로 바로잡고 A-CEN→CEN, A-ROOM→ROM으로 옮긴 뒤 사람이 확인한다. 실무 도면이므로 T7의 허용 목록을 켜 둔 상태에서 진행한다.
2. 개정한 스킬 절차대로 `export_snapshot`과 `read_drawing`으로 그리드와 코어를 읽는다.
3. 객실 배치를 배치 규칙(반복·대칭) 명세로 작성해 `draw_batch`로 넣는다.
4. 치수·버블·실명도 같은 방식으로 넣는다.
5. `check_standard`로 검사하고, 고칠 목록이 있으면 `fix`로 고친다.
6. 같은 요청을 한 번 더 보내 '이미 완료'로 처리되는지, 중간 실패를 한 번 일으켜 복구되는지 확인한다.
7. 10월 12일 작업 결과(객실 27개, 객체 943개)와 비교한다.

**판정 기준**(로드맵의 0단계 평가 항목)

| 항목 | 기준 |
| --- | --- |
| 재현 | 즉석 LISP·`send_command` 없이 새 툴 호출만으로 완성 |
| 표준 | 위반 0건. 검사하지 못한 항목은 목록으로 보고 |
| 재현성 | 같은 명세를 빈 사본에 두 번 적용하면 같은 결과 |
| 원본 보호 | 재실행, 중간 실패, 수동 수정 시나리오가 D5대로 처리됨 |
| 지원 범위 | 지원 객체와 검사 항목이 문서로 정리돼 있음 |
| 소요 시간 | 측정해 기록. 수치 기준은 이번 결과를 기준선으로 삼아 다음 단계에서 정한다 |

**통과 뒤**: BricsCAD에서 같은 시험을 돌려 호환 상태를 기록하고, 0-B 계획을 쓴다.

## 테스트와 작업 방식

엔진 테스트는 CAD 없이 매 커밋마다 돌고, CAD 연동 테스트는 Windows PC에서 병합 전에 돌린다.

| 종류 | 위치 | 실행 환경 | 언제 |
| --- | --- | --- | --- |
| 엔진 단위 테스트 | `tests/engine/` | Linux·Windows, CAD 불필요 | 모든 커밋(GitHub Actions) |
| 골든 파일 테스트 | `tests/engine/golden/` | 같음 | 검사·작성 로직을 바꿀 때 |
| CAD 연동 테스트 | `tests/cad/` | Windows + GstarCAD 2021 | PR 병합 전 수동 실행 |
| 통과 시험 | T10 절차 | Windows + GstarCAD 2021 | 0-A 마무리 |

시험 데이터는 회사 템플릿으로 만든 합성 도면을 쓴다. 실무 도면은 T10에서만, 허용 목록을 켜 둔 상태로 쓴다.

**Claude Code로 진행하는 방법**

1. 저장소 `docs/`에 로드맵·구조 결정·이 계획의 Markdown 사본을 두고 `CLAUDE.md`에서 가리킨다(T1).
2. 작업 하나를 브랜치 하나로 진행하고, 시작할 때 해당 작업 명세를 Claude Code에 넘긴다.
3. 엔진 작업(T1, T2 일부, T4, T5, T8)은 어디서나 할 수 있다. CAD 연동 작업(T0, T3, T6, T7, T10)은 GstarCAD가 있는 Windows PC에서 한다.
4. PR에는 엔진 테스트 통과, 해당 작업의 완료 기준 확인, CAD 연동 테스트 결과(해당할 때)를 적는다.
5. 계획과 다르게 구현하거나 결정을 바꿔야 하면, 코드보다 이 문서나 구조 결정 문서를 먼저 고친다.
