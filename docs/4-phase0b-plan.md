# arcaid-cad 0-B 실행 계획

Oct 17, 2026 · @Jeonglo Choi

0-B에서는 기존 객체의 이동·삭제·속성 변경을 0-A와 같은 보호 장치로 처리하는 `apply_changes`를 만든다. 작업은 7개(B0~B6)이다. 통과 판정은 B5에서 한다. 당산동 결과 사본과 원본 사본에서 실무형 변경을 재현하는 시험이다. 삭제를 0-B에 넣을지는 B0의 삭제 복귀 확인으로 정한다.

## 전제와 범위

0-B는 D5가 정한 변경(이동·삭제·속성 변경)을 선·폴리라인·문자·블록 참조에 한정해 다룬다. 회전·대칭은 0-B를 통과한 뒤 같은 경로에 더한다(2026-10-17 결정).

- **전제 결정**: D5(0-B 범위), D2(`apply_changes`), D7(GstarCAD 2021 기준, BricsCAD 호환 확인), D8(A안)
- **0-A에서 이어받는 것**: 적용 직전 확인, 묶음 안에서는 COM 호출만, 스냅샷 핸들 집합 복귀 확인, 기준 상태 갱신, GUARD, D2 결과 형식. 0-A의 GUARD 누락 경로(사후 스냅샷 실패)는 B2에서 함께 고친다.
- **변경 종류**: 이동(평행이동 dx, dy), 삭제, 속성 변경(레이어·색·선종류·선굵기, 문자 내용, 블록 속성값)
- **대상 객체**: 선, LWPOLYLINE, 문자(TEXT), 블록 참조(D5)
- **거부**: 지원 밖 객체가 하나라도 섞이면 요청 전체를 거부하고 목록을 보고한다. 반응자·그룹이 걸린 객체(연관 해치 경계, 연관 치수 대상, 그룹 구성원)도 거부한다.
- **대상 범위**: 엔진 객체(태그 있음)와 사람 객체(태그 없음)를 모두 다룬다. 사람 객체에는 태그를 새로 달지 않는다.
- **범위 밖**: 회전·대칭·배율, 원·호·해치·치수·MTEXT, 블록 정의 내부, 레이아웃, Xref 내부

## 변경 명세

변경 명세는 기준 스냅샷 하나와, 그 스냅샷에서 고른 대상에 대한 변경 목록이다.

```json
{"schema_version": 1, "standard": "heo-2026@2026.1", "op": "room-07-shift",
 "target": {"drawing_id": "{…}", "snapshot_id": "snap-…"},
 "changes": [
  {"id": "c1", "select": {"op": "t10-rooms", "path_prefix": "room/7/"}, "action": "move", "delta": [600, 0]},
  {"id": "c2", "select": {"handles": ["1A2F", "1A30"]}, "action": "delete"},
  {"id": "c3", "select": {"handles": ["2B07"]}, "action": "set", "props": {"text": "객실(A)"}},
  {"id": "c4", "select": {"oids": ["t10-annotations:X3"]}, "action": "set", "props": {"attribs": {"축열": "X4"}}}]}
```

- **기준 스냅샷**: `target.snapshot_id`는 필수다. 그 스냅샷은 활성 문서의 열린 문서 사본이어야 한다(출처 경로 일치). 도면 ID만으로는 판단하지 않는다. 사본끼리 같을 수 있기 때문이다(T10에서 확인).
- **대상 확정**: 대상은 그 스냅샷의 핸들로 확정한다. 형상이 비슷한 다른 객체로 대체하지 않는다.
- **고르기**
    - `handles`: `get_selection` 또는 `read_drawing` 전체 결과에서 얻는다.
    - `oids`: 형식은 `op:경로`.
    - `op` + `path_prefix`: 엔진 객체 묶음. `get_selection`의 결과가 잘릴 만큼 큰 묶음은 이것으로 고른다.
- **중복 금지**: 한 객체는 변경 하나에만 들어간다. 겹치면 명세를 거부한다(거부 코드 `CHG_*`).

## 판정 규칙

엔진은 대상마다 before(기준 스냅샷의 상태)와 after(변경 뒤 상태)를 계산하고, 도면 안 적용 기록과 지금 상태를 함께 보고 판정한다.

- **비교**: 변경 판정용 상태로 한다. 원시 좌표는 거리 0.01mm 이하, 각도·배율은 따로 비교한다. 정렬 문자는 두 기준점을 모두, 블록 속성은 값·위치·정렬을 본다. 태그의 state 해시 방식은 0-A 태그와 호환되도록 바꾸지 않는다.
- **적용 기록**: 적용에 성공하면 도면 안 ARCAID 사전에 op별 레코드(입력 해시, 확정 대상 핸들, 결과)를 같은 Undo 묶음 안에서 남긴다. 이 기록이 있어야 정상 삭제와 사람이 지운 것을 구분할 수 있다.

| 도면 안 기록 | 지금 상태 | 판정 |
| --- | --- | --- |
| 없음 | 대상 모두 before | 적용 |
| 없음 | 하나라도 before가 아님(사람이 고침·없어짐·일부 적용) | 충돌, 아무것도 바꾸지 않음 |
| 같은 op·같은 입력 | 대상 모두 after(삭제 대상은 없음) | 이미 완료, 건너뜀 |
| 같은 op·같은 입력 | after가 아닌 대상 있음 | 충돌(적용 뒤 바뀜) |
| 같은 op·다른 입력 | 상관없음 | 충돌(D5) |

- **엔진 객체 수동 수정**: 지금 상태가 태그 state와 다르면 사람이 고친 것이다. `overwrite_manual=true`일 때만 바꾼다. 이 옵션도 '읽은 뒤 바뀜' 충돌은 면제하지 않는다.
- **적용 전 거부**
    - 원래·목적 레이어가 잠김·동결·꺼짐인 경우
    - 대상 도면에 없는 레이어·선종류로 바꾸는 경우(`ensure_standard_layers`를 먼저 부른다)
    - 없는 속성 태그, 상수 속성
    - 단위가 mm가 아닌 도면
- **적용 뒤**
    - 엔진 객체는 태그의 op·oid·path·in·ver를 그대로 두고 state만 갱신한다(묶음 안).
    - 대상이 아닌 객체의 상태가 그대로인지 확인한다.
    - 바꾼 객체에 새로 생긴 검사 위반은 되돌리지 않고 보고한다.
- **되돌리기**
    - 묶음 안에서 실패하면 `UNDO 1`을 보낸다. 단 아무 변경도 하기 전에 실패했으면 보내지 않는다.
    - 그다음 핸들 집합, 대상의 before 상태, 적용 기록이 없어졌는지를 확인한다.
    - 이동·속성 변경이 덜 돌아왔으면 지금 after로 확인된 객체에만 역변경을 한 번 하고 다시 확인한다.
    - 삭제가 같은 핸들로 돌아오지 않으면 확인 불가다. 백업 DXF 경로는 참고로만 알린다.
- **확인 불가와 중단**: 확인 불가, 타임아웃·연결 끊김·취소에서는 모두 GUARD를 건다. 사용자가 확인하고 `resume_after_unverified`로 다시 부르기 전까지 보호된 변경을 멈춘다.

## 작업 순서

&#91;embedded content: 작업 의존 관계 · B0~B6\]

1. B0 사전 검증(CAD, 삭제 복귀 관문)과 B1 명세와 판정(엔진, CAD 불필요)을 함께 시작한다.
2. B2 보호된 경로(`apply_changes`, GUARD)
3. B3 MCP 툴(저수준 툴 보호)
4. B4 스킬 개정(변경 절차·예제)
5. B5 통과 시험(GstarCAD, 0-B 판정)
6. B6 BricsCAD 호환

B1은 CAD 없이 B0과 함께 시작하고, B2는 둘이 끝난 뒤 시작한다. B6의 0-A 부분(기존 시험을 BricsCAD로 다시 돌리기)은 언제든 할 수 있고, 0-B 부분은 B5를 통과한 뒤에 한다.

## 작업 명세

작업마다 내용, 테스트, 완료 기준을 적는다. 삭제를 0-B에 넣을지는 B0의 E10으로 정한다.

### B0 · 사전 검증

GstarCAD에서 한다. 실험 코드는 `spikes/b0_*.py`, 결과는 `docs/spike-report.md`의 'B0' 절에 적는다. 시나리오마다 새 사본에서, 이전 작업 표시선을 먼저 그어 둔다.

- **E10 삭제 복귀(필수 관문)**: 묶음 안 COM Delete → `UNDO 1`. 대상은 선·LWPOLYLINE·TEXT·속성 있는 블록(XDATA 포함). 같은 핸들·태그·속성으로 돌아오는가, 이전 작업은 그대로인가.
- **E11 이동·속성 쓰기**: COM Move, TextString, 블록 속성 TextString, Layer·색(트루컬러)·선종류·선굵기 → `UNDO 1`. 정렬 문자 두 기준점과 속성 위치가 이동을 따라오는가. 정밀도 0.01mm.
- **E12 실패 지점**: 첫 COM 호출 실패(묶음만 열림), 목록 중간 예외, 사후 확인 실패, 타임아웃. 각각 Undo 범위가 맞는가, 이전 작업이 남는가. D5의 남은 확인 항목이다.
- **E13 적용 기록**: COM으로 ARCAID 사전에 XRECORD를 쓰고 Export 사본에서 읽히는가. `UNDO 1`로 지워지는가.
- **E14 레이어·속성 행렬**: 원래·목적 레이어의 잠김·동결·꺼짐, 없는 선종류, 없는 속성 태그, 상수 속성에서 COM이 오류를 내는가, 조용히 무시하는가.
- **E15 관계**: 연관 해치 경계, 연관 치수 대상, 그룹 구성원을 이동·삭제할 때 다른 객체에 생기는 변화와 반응자 감지 방법.
- **E16 규모**: 객체 100·1,000·5,000개 변경 시간. 이 결과로 한 요청의 객체 상한을 정한다.
- **E17 대안**: Undo가 덜 돌린 경우 역변경 복귀. 삭제 객체를 다시 넣었을 때의 핸들.
- **관찰**: T9·T10에서 본 Export 뒤 saved True→False 경고의 원인.
- **완료 기준**: 항목별 결과와 결정(상한, 삭제 포함 여부, 적용 기록 방식, 거부 규칙)을 기록한다. E10이 실패하면 삭제를 빼는 결정 문서 변경안을 사용자에게 보인다.

### B1 · 변경 명세와 판정

엔진 작업이다(`src/engine/changes.py`, CAD 불필요).

- **내용**: 명세 읽기·검증(`CHG_*`), 고르기 전개, 변경 판정용 상태, before·after 계산, 적용 기록 읽기, 판정표 구현.
- **테스트**: 판정표의 모든 칸. 정렬 문자 두 기준점·속성 위치 이동, 0.009/0.011mm 경계. 같은 객체 중복 지정, 지원 밖·반응자 객체 거부, 없는 레이어·속성 태그, 상한 초과. MCP·COM 모듈을 불러오지 않는다.

### B2 · apply_changes 보호된 경로

MCP 작업이다(`src/apply_service.py`, `src/cad_controller.py`).

- **흐름**: 거부 확인 → 기준 스냅샷 출처 확인 → 적용 전 스냅샷·판정 → 묶음 안 COM 변경·state 갱신·적용 기록 → 사본으로 결과 확인(after 일치, 대상이 아닌 객체 불변, 핸들 변화 = 삭제 대상) → 사후 스냅샷·검사 → 보고. 실패하면 판정 규칙의 '되돌리기'를 따른다.
- **컨트롤러에 더할 것**: 핸들 묶음 이동, 문자 내용·블록 속성 쓰기, 적용 기록 쓰기. 삭제(`delete_handles`)와 속성 쓰기(`set_props`)는 이미 있다.
- **0-A 보강**: 모든 unverified 반환(draw_batch·fix의 사후 스냅샷 실패 포함)에서 GUARD를 건다. 재실행 충돌 문구의 '새 op로 보내거나' 안내를 지운다.
- **테스트**(`tests/cad`): 실패 주입 시 삭제를 포함해 recovered, 이전 작업 보존. 첫 호출 실패 때 UNDO를 보내지 않음. 적용 전 사람 수정이 끼어들면 conflict. 재전송은 skip, 같은 op·다른 입력은 conflict. 잠김·동결 레이어 거부. 모든 확인 불가 경로에서 GUARD(draw_batch·fix 회귀 포함).

### B3 · MCP 툴과 저수준 툴 보호

`src/server.py`, `config/egress.yaml`.

- **apply_changes 툴**: 툴 46개가 된다. 설명문, 툴 목록 시험, 새 결과 필드의 정책 분류를 고친다.
- **고치는 저수준 툴**(erase·move·rotate·scale): 태그 객체를 거절한다. 핸들 검사와 변경은 같은 COM 작업 안에서 한다. 이동 요청은 `apply_changes`로, 회전·배율 요청은 '보호된 경로 미지원'으로 안내한다.
- **만드는 저수준 툴**(copy·mirror·배열·offset, 원본 유지): 새 객체의 ARCAID 태그만 지우고 다른 앱 XDATA는 남긴다. 태그 제거에 실패하면 실패로 보고한다.
- **한계**: `send_command`·`run_lisp`·undo·redo는 통제하지 못한다. 툴 설명과 스킬에 적는다.

### B4 · 스킬 개정

- **변경 절차**: `export_snapshot`·`read_drawing` 또는 `get_selection`(잘리면 limit을 올리거나 op+path_prefix로 고름) → 변경 명세 → `apply_changes` → `check_standard` → 보고.
- 충돌·확인 불가에서는 멈춘다. 예제와 zip을 갱신한다.

## 0-B 통과 시험(B5)

당산동 결과 사본(엔진 객체)과 원본 사본(사람 객체)에서 실무형 변경 세 가지를 `apply_changes`만으로 재현하고, 보호 장치를 하나씩 시험한다.

**준비**: `C:\arcaid\work`의 새 폴더에 사본 두 가지를 둔다. A3 1/200(k=200)이다.

- T10 결과 사본: 엔진 객체다.
- 당산동 원본 사본: T10처럼 헤더만 mm로 고친다. 태그 없는 사람 객체다.

**절차**

1. 변경 요청 세 가지를 보낸다.
    - 객실 1실 상세 전체 이동(엔진 객체 약 640개, op+path_prefix)
    - 가구·창 일부 삭제(B0을 통과한 경우), 실명과 축열 버블 번호 변경
    - 원본 사본의 사람 객체 이동·삭제·문자 변경
2. 기대 결과는 시험 코드가 기준 스냅샷에서 독립 계산한다. `changes.py`의 계산을 쓰지 않는다.
3. `check_standard`로 바꾼 객체의 새 위반을 확인한다.
4. 보호 장치를 시험한다.
    - 같은 요청 재전송 → 건너뜀. 같은 op·다른 입력 → 충돌.
    - 적용 전 사람 수정(대상 이동·문자 변경·삭제)과 엔진 객체 수동 수정 → 각각 별도 사본에서 충돌, 변경 없음.
    - 실패 주입 → recovered. 삭제 객체는 같은 핸들·태그·속성으로, 이전 작업은 그대로.
5. 독립 사본 A/B에 같은 요청을 적용하고 대조한다.
6. 공개 MCP(stdio)로도 같은 흐름을 한 번 실행한다.

| 항목 | 기준 |

## 0-A에서 넘어온 후속

0-B 안에서는 세 가지만 하고, 나머지는 구현 범위를 넓히지 않고 상태만 관리한다.

- **0-B 안에서**: GUARD 누락 경로와 충돌 문구(B2), saved 경고 원인(B0)
- **0-B 밖에서**
    - 표준 프로파일 확장: 상세 블록(HEO_BATH·BED·DOOR·WIN) 등록, PAK1·TXT1 문자 용도, 계단·배치도의 미등록 설계 가정 수치
    - 명세·엔진: 타원 종류 추가
    - 툴: 활성 도면 LTSCALE 맞추기
    - 표준매뉴얼 DWG에 비주석 치수 개정 반영(사용자 작업 대기)

## 테스트와 작업 방식

0-A와 같은 방식으로 진행한다.

- 작업 하나 = 브랜치 하나 = PR 하나.
- 엔진 시험은 CI(Ubuntu·Windows)에서, CAD 시험은 병합 전 로컬에서 돌린다.
- 계획과 다르게 가야 하면 코드보다 문서를 먼저 고친다.
- 시험 데이터는 합성 도면이 기본이고, 실무 도면은 B5에서만 쓴다.
